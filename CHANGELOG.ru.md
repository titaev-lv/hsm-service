# Changelog 

## v2.1.0 - 2026-03-25

### Новые возможности
- Добавлен reconcile KEK-версий при старте: `init-hsm.sh` синхронизирует версии из `metadata.yaml` с фактическим состоянием токена HSM
- Повышена переносимость инициализации токена: переход с фиксированного `--slot 0` на `--free` в SoftHSM
- Расширена структура PCI DSS тестов: проверки декомпозированы на отдельные скрипты

### Исправления безопасности
- Закрыты дополнительные замечания статического анализа в admin/runtime путях (`G115`, `G407`, `G703`)
- Улучшен security baseline Docker-образа: зафиксирована версия Alpine и усилено покрытие security scan
- Исправлены необработанные ошибки (`G104`) в тестово-комплаенсных сценариях

### Надежность
- Исправлено ложное optional-skip поведение в master runner: поправлен `sed` pipeline фазы Security Scans
- Проверка KEK при старте переведена на фактическое наличие в HSM (`list-kek --verbose`), а не только на записи в metadata
- Усилена стабильность запуска интеграционного окружения и устранены edge-case проблемы инициализации

### Тестирование
- Усилены integration/E2E сценарии для изолированного тестового compose окружения (`config-test.yaml`, `metadata-test.yaml`, `revoked-test.yaml`)
- Повышена устойчивость сценариев key rotation / disaster recovery / ACL real-time reload
- Расширено покрытие dry-run и safe-path сценариев, а также оркестрации security/compliance тестов
- Security Scans оставлены опциональными, но доведены до полного исполнимого прогона в подготовленном окружении

### Комплаенс
- PCI DSS проверки декомпозированы на отдельные сценарии, исправлена обработка warning/error в тестах
- Сохранена явная warning-семантика для опционального split-knowledge и синхронизирован текущий статус реализации

### Документация
- Обновлены архитектурные/плановые/runbook документы в части усиления тестового процесса и уточнения комплаенс-статуса

## v2.0.1 - 2026-03-02

### Новые возможности
- Унифицирована конфигурация сервиса в едином `config.yaml` (единый поток загрузки server/config)
- Добавлены явные настройки таймаутов и лимитов сервера (`read`, `write`, `idle`, `read_header`, `shutdown_grace`, `max_header_bytes`)
- Добавлены настройки вывода логов в stdout и соответствующая конфигурация

### Исправления безопасности
- Устранены риски переполнения при разборе `server.port` (`G115/CWE-190`): убраны небезопасные преобразования `uint64 -> int` и `int -> uint64`
- Добавлена строгая числовая валидация порта (только конечные значения, целые для float, проверки диапазона int с учетом архитектуры)

### Надежность
- Упрощена обработка потока access-логов с сохранением точного `duration_ms`
- Обновлены настройки `hsm-service` в `docker-compose.yml`

### Тестирование
- Добавлены регрессионные тесты `parsePort` на переполнение и невалидные числовые значения

### Документация
- Обновлены архитектурная, production, troubleshooting, monitoring документация и README в соответствии с унифицированной конфигурацией и логированием
- Обновлены плановые документы разработки и метаданные версии
